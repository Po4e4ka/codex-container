# Песочница Codex в Docker

etp.sh сохраняет прежние Docker flags пользователя: seccomp/appArmor unconfined,
SYS_ADMIN/NET_ADMIN, privileged и userns=host. Добавлены host-gateway для
local.flami.pro и group65534; группа Docker socket по-прежнему определяется
динамически. Запуск по умолчанию: codex --sandbox workspace-write
-c sandbox_workspace_write.network_access=true. Approval policy on-request
и пользовательский config не менялись. После изменения нужен новый контейнер,
пересборка образа не требуется. Во временном контейнере bwrap под UID1000
с этими flags успешно создал namespaces и выполнил команду (BWRAP_OK).

# Быстрое переключение VPN

В каталоге запуска (`~/ai` на хосте, `~/project` внутри агента):

```bash
./switch msk   # Москва → Германия
./switch ke    # Кения
./switch de    # Германия напрямую, резерв
./switch       # показать выбор следующего запуска
```

После выбора закрыть старый контейнер и запустить `./etp.sh` на хосте.
Команды сохраняют `.vpn-profile` и не изменяют работающий контейнер.
Пересборка образа не нужна. Пароли/ключи в профиль не записываются.
Новый контейнер создаёт отдельный TUN config с исключением адреса SSH входа,
использует существующий SSH key и strict known_hosts. msk использует ProxyCommand
через Москву до Германии, поэтому выход остаётся немецким. ke использует SSH
Кении напрямую. Если выбранный узел недоступен, запуск останавливается:
автоматического перехода на другой профиль нет. Выбрать msk/de можно без сети.

Проверено2026-11-05: полный новый msk контейнер, TUN/DNS/HTTPS,
exit171.22.119.96 и реальный Codex account/read0.89секунды.
ke корректен синтаксически, но SSH Kenya22 сейчас timeout; runtime не подтверждён.
Текущая сессия остаётся de, следующий запуск выбран msk.

# Запуск через Германию (исправлено после bootstrap timeout)

На хосте: cd ~/ai, затем ./etp.sh. Пересборка не нужна.
Закройте старый ai-agent перед новым запуском с тем же именем.
Транспорт по умолчанию: существующий SSH Germany22 → SOCKS → sing-box TUN.
Нужны текущие ~/.ssh/id_rsa и known_hosts. DNS через TCP в туннеле.
Это TCP-only транспорт; остальные серверные VPN не менялись.

Проверка: новый контейнер, полный startup, IP171.22.119.96 и реальный
Codex account/read OK/account present за1секунду. Скрипт повторной проверки:
python3 /home/codex/project/check-codex-account.py внутри работающего контейнера.
Без хостовой Amnezia путь ещё требует пользовательской проверки.
Предыдущий Shadowsocks8388 оказался нестабильным и больше не является default.

# Сборка через VPN работающего агента

Если на хосте загрузки недоступны, а контейнер `ai-agent` уже работает с VPN:

```bash
cd ~/ai
./build.sh --vpn --update
```

Команду можно выполнить внутри агента с доступом к Docker socket хоста либо
на самом хосте из каталога этого репозитория. Нужны Docker и Buildx.
Для другого имени VPN-контейнера:

```bash
VPN_CONTAINER=my-agent ./build.sh --vpn --update
```

BuildKit запускается в отдельном контейнере с сетью работающего VPN-контейнера.
Загрузки базового образа и команды Dockerfile используют эту сеть.
При первом запуске Docker хоста должен суметь скачать `moby/buildkit:buildx-stable-1`;
последующие запуски используют локальный образ и кеш сборщика.
Флаг `--update` обновляет слой установки Codex, остальные слои используют кеш.

Результат загружается через `--load` в Docker того же хоста как `ai-agent:latest`.
Работающий агент продолжает использовать прежний образ. Следующий контейнер,
созданный из `ai-agent:latest` привычной командой запуска с VPN-конфигами и томами,
использует новый образ. `docker restart` существующего контейнера образ не обновляет.
Дождитесь успешного завершения сборки, прежде чем завершать текущего агента.

Для переноса на другой Docker-хост после успешной сборки:

```bash
docker save ai-agent:latest | gzip > ai-agent.tar.gz
# Перенести архив на целевой хост, затем там:
gzip -dc ai-agent.tar.gz | docker load
```

Архитектура целевого хоста должна совпадать с архитектурой собранного образа.
VPN-конфиги передаются отдельно существующими bind mounts; они не входят в образ.

Обычная сборка сохраняется: `./build.sh` или `./build.sh --update`.
Сборщик VPN привязан к конкретному контейнеру; после пересоздания агента скрипт
создаст новый сборщик. Когда старый больше не нужен, его можно удалить командой
`docker buildx rm ai-vpn-<первые 12 символов ID старого контейнера>`.

Справка Docker: [настройка сети сборщика и загрузка образа в Docker хоста](https://docs.docker.com/build/builders/drivers/docker-container/).

# Перенос контейнера на другой компьютер

Репозиторий: `git@github.com:Po4e4ka/codex-container.git`.
Нужен Linux с Docker Engine, Buildx, Python 3 и доступом к `/dev/net/tun`.
На Windows запускайте из Linux/WSL2; новый запуск на macOS отдельно не проверен.

```bash
git clone git@github.com:Po4e4ka/codex-container.git ~/ai
cd ~/ai
./build.sh
```

Если загрузки для сборки на новом компьютере недоступны, перенесите готовый
образ с текущего хоста (архитектуры компьютеров должны совпадать):

```bash
docker save ai-agent:latest | gzip > ai-agent.tar.gz
# После передачи архива на новый компьютер:
gzip -dc ai-agent.tar.gz | docker load
```

`./build.sh --vpn` собирает образ через уже работающий контейнер `ai-agent`.
На новом компьютере без работающего VPN этот вариант не подходит.

## Отдельный SSH VPN-клиент

Приватный комплект передаётся отдельно от Git защищённым способом. Скопируйте
папку `vpn-client` в `~/ai/.private/vpn-client`. После регистрации публичного
ключа на серверах активируйте его:

```bash
cd ~/ai
cp .private/vpn-client/client.json .vpn-client.json
chmod 700 .private .private/vpn-client
chmod 600 .vpn-client.json .private/vpn-client/id_ed25519
./switch msk
./etp.sh
```

Новый клиент использует отдельный ключ и пользователя `vpn-codex-pc`.
Москва — только SSH-переход до Германии; Германия — TCP SOCKS и TUN/DNS.
Доступ к shell, PTY, агенту SSH и X11 для этого ключа запрещён.
Приватный ключ не защищён паролем, так как VPN запускается автоматически.
Успешный запуск требует регистрации ключа на обоих серверах. Её статус и
проверки указываются в сопровождающем локальном файле `STATUS.md` комплекта.
Кения для этого нового клиента не подключена; используйте `msk` или `de`.

Если отдельный комплект не активирован, сохраняется прежний запуск через
`~/.ssh/id_rsa` и `~/.ssh/known_hosts`. Административный ключ для нового
VPN-клиента переносить не требуется. Шаблон `sing-box.example.json` не содержит
секретов и используется автоматически, если нет локального `sing-box.json`.
Xray-конфиг при стандартном SSH-запуске не требуется.

## Данные вне репозитория

- Создайте на новом хосте `~/.codex` и авторизуйтесь в Codex при первом запуске.
  Для сохранения истории/настроек перенесите собственный каталог `~/.codex`
  отдельно защищённым способом; он может содержать токены и личные данные.
- Перенесите нужные проекты в `~/www` — каталог монтируется автоматически.
- Git/SSH-доступ к исходникам настройте отдельно в `~/.ssh` нового компьютера.
- Старые WireGuard/Xray-конфиги, резервные копии и настройки IDE в Git не входят.

После запуска проверьте фактическую авторизацию внутри контейнера:

```bash
python3 /home/codex/project/check-codex-account.py
```

`./switch` меняет только следующий запуск. Текущую сессию он не прерывает.
При проблемах с московским входом: `./switch de`, затем новый `./etp.sh`.
Откат нового клиента: удалить только пользователя `vpn-codex-pc` на двух серверах
после остановки его сессий; старые пользователи, ключи и серверные службы не меняются.
